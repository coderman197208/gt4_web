## Why

GT4 当前已经具备 C++ -> Redis -> Node.js -> WebSocket -> Vue 的实时数据链路，以及 Vue -> WebSocket -> Redis -> C++ 的命令下发链路，但还没有独立的报警模型。现有系统只能传递原始点位或业务数据，不能表达报警的产生、持续、恢复、人工确认和历史追溯，也不能按照操作员所属区域限制报警可见范围。

这使得报警相关流程存在三个核心缺口。第一，前端无法把未确认报警和已确认报警作出明确区分，操作员也没有统一的人工确认入口。第二，后端没有独立的报警存储和审计结构，无法可靠保存活动报警、恢复时间和确认记录。第三，当前登录上下文只有基础用户信息，没有区域授权模型，无法满足“按登录用户所在区域显示报警”的业务要求。

这个 change 需要为项目引入一套独立的报警模块，使业务后端能够发布报警，Web 后端能够持久化并按区域分发报警，前端能够以符合当前 HMI 风格的方式展示和确认报警，并为后续拆分 specs 和 tasks 提供明确边界。

## What Changes

- 新增一套独立于实时 tag 推送之外的报警事件链路，支持 C++ 业务后端发布报警、Web 后端持久化报警、维护活动态与历史态，并处理报警恢复与人工确认生命周期。
- 新增报警分区与用户区域授权模型，使报警查询和实时推送都按用户所属区域过滤，而不是由前端接收全量数据后再本地裁剪。
- 新增面向操作员的报警中心界面，支持活动报警展示、未确认与已确认差异化显示、报警详情查看和人工确认操作。
- 定义报警数据存储方案、共享数据契约、后端 API 与 Socket 事件边界，以及 C++ 侧统一报警发布接口，为后续实现和任务拆解提供清晰范围。

## Capabilities

### New Capabilities

- `alarm-event-lifecycle`: 系统必须能够接收 C++ 发布的报警事件，持久化活动报警与历史操作记录，并将报警恢复与人工确认作为独立状态管理。
- `alarm-area-access-control`: 系统必须能够维护报警区域与用户区域授权关系，并保证报警查询和实时推送仅返回用户有权查看的区域范围。
- `alarm-center-operations`: 系统必须为前端提供报警中心交互，支持显示报警等级与状态、区分未确认和已确认报警、查看报警详情以及执行人工确认。

### Modified Capabilities

- None.

## Impact

- 受影响的 C++ 范围包括 `gt4_app` 中需要产生报警的业务模块、共享报警发布接口，以及在需要时接收报警确认回写的命令处理入口。
- 受影响的 Web 后端范围包括新的报警 API、报警事件持久化服务、Redis 订阅与处理逻辑、Socket.IO 区域分发逻辑，以及登录用户上下文中的区域信息扩展。
- 受影响的前端范围包括用户登录后的区域上下文、页头报警入口、报警中心组件或视图、报警状态 store，以及对应的 API/Socket 数据接入。
- 受影响的共享契约范围包括 `packages/shared` 中新增的报警事件、报警区域、确认请求与前端展示模型类型。
- 受影响的数据层范围包括 PostgreSQL 中新增的报警主表、报警操作日志表、报警区域表和用户区域关联表，以及 Redis 中新增的报警事件键与频道约定。
