# alarm-center-visual-alignment Specification

## Purpose

定义报警中心与主监控页之间的视觉对齐要求，确保报警中心在保留状态优先级和处理效率的同时，使用与 MainMonitorView 一致的 HMI 工业界面语言。

## ADDED Requirements

### Requirement: 系统必须以与 MainMonitorView 同源的 HMI 视觉语言展示报警中心

系统 SHALL 在报警中心中使用与 MainMonitorView、HomePage 和 AppHeader 一致的浅色工业 HMI 视觉基线，包括分层面板、清晰边框、内嵌层次和稳定的信息分区，而不是切换到独立的暗黑抽屉主题。

#### Scenario: 打开报警中心时保持与主监控页一致的面板语言

- **GIVEN** 操作员位于 `HomePage` 壳层中的任一业务页面
- **WHEN** 操作员点击页头报警入口打开报警中心
- **THEN** 报警中心主体必须使用与 `MainMonitorView` 同源的浅灰工业面板风格
- **AND** 标题区、摘要区、筛选区、列表区和详情区必须以明确框体分区呈现
- **AND** 报警中心主体不得再表现为与应用壳层明显割裂的整面暗黑主题

### Requirement: 系统必须在统一浅色 HMI 框架中清晰区分报警优先级和处理状态

系统 SHALL 在统一浅色工业框架中表达报警等级与状态差异，使未确认和高等级报警仍然具有最高视觉优先级，但已确认和已恢复状态会被适度弱化，且整个区分过程不依赖全局暗背景对比。

#### Scenario: 未确认活动报警在浅色主题下仍具最高优先级

- **GIVEN** 某条报警 `condition_state = active` 且 `ack_state = unacked`
- **WHEN** 前端渲染报警中心列表和详情
- **THEN** 该报警必须通过高优先级的局部强调方式被明显区分
- **AND** 该强调必须建立在统一浅色 HMI 面板之上
- **AND** 页头未确认数量必须继续与该状态保持一致

#### Scenario: 已确认或已恢复报警被弱化但仍保持可读

- **GIVEN** 某条报警已经确认或恢复
- **WHEN** 前端渲染该报警
- **THEN** 系统必须降低该报警的视觉强度
- **AND** 系统不得因为弱化而使报警等级、区域或时间信息不可读

### Requirement: 系统必须保持适合 HMI 处理场景的高密度右侧双栏布局

系统 SHALL 继续使用右侧滑出式报警中心，并在该面板内保持“摘要/筛选/页签 + 列表/详情”的高密度处理结构，使操作员无需跳转到独立页面即可完成查看、筛选和确认。

#### Scenario: 标准 HMI 分辨率下列表和详情同时可用

- **GIVEN** 系统运行在 `1920 x 1080` 的 HMI 视图基线下
- **WHEN** 操作员打开报警中心
- **THEN** 报警摘要、筛选、页签、报警列表和详情区必须全部保持在右侧面板内部
- **AND** 操作员必须能够在不离开当前页面的情况下完成查看和确认
- **AND** 系统不得引入浏览器级滚动条

### Requirement: 系统必须让页头报警入口与报警中心风格一致

系统 SHALL 让页头报警入口按钮、状态点和未确认数量角标与报警中心面板保持统一的工业 HMI 风格，同时继续保证各状态下的可读性和可点击性。

#### Scenario: 页头报警入口在不同报警数量下都保持统一风格与可读性

- **GIVEN** 页头显示报警入口按钮
- **WHEN** 未确认数量为 `0` 或大于 `0`
- **THEN** 按钮的底色、边框和状态点必须与报警中心面板属于同一套视觉语言
- **AND** 未确认数量角标必须在各种状态下清晰可辨
