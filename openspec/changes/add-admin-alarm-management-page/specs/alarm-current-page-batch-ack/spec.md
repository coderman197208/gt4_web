# alarm-current-page-batch-ack Specification

## Purpose

定义 admin 在报警管理页中对当前页可见未确认报警执行批量确认的接口语义、日志写入规则和结果反馈方式。

## ADDED Requirements

### Requirement: 系统必须仅允许 admin 执行批量确认

系统 SHALL 仅向 `admin` 暴露批量确认能力；非 admin 用户不得通过该接口批量确认报警。

#### Scenario: 普通用户尝试调用批量确认接口时被拒绝

- **GIVEN** 当前登录用户角色为 `user`
- **WHEN** 客户端请求 `POST /api/admin/alarms/batch-ack`
- **THEN** 系统必须拒绝该请求
- **AND** 系统不得确认任意报警记录

### Requirement: 系统必须通过显式提交的当前页报警项列表执行批量确认

系统 SHALL 接收由前端显式提交的当前页可见未确认报警项集合，并基于每项提供的 `alarm_id` 与 `expected_version` 执行批量确认，而不是要求服务端根据筛选条件重新计算当前页。

#### Scenario: admin 提交当前页可见未确认项列表时只处理这些项目

- **GIVEN** 管理页当前结果页中存在多条可见报警
- **AND** 其中部分报警处于 `ack_state = unacked`
- **WHEN** admin 请求 `POST /api/admin/alarms/batch-ack`，并提交这些当前页可见未确认项的 `alarm_id` 与 `expected_version`
- **THEN** 系统必须只尝试确认请求体中显式提交的报警项
- **AND** 系统不得要求前端再次提交查询条件来重算“当前页”定义

### Requirement: 系统必须允许为批量确认提交统一备注并写入每条成功确认日志

系统 SHALL 允许 admin 在一次批量确认请求中提交一条统一备注，并将其写入每条成功确认报警的确认日志；未成功确认的报警不得产生新的确认日志。

#### Scenario: admin 提交统一备注后每条成功确认日志都包含该备注

- **GIVEN** admin 准备对当前页多条未确认报警执行批量确认
- **AND** 请求体中包含统一 `operator_note`
- **WHEN** 系统成功确认其中一条或多条报警
- **THEN** 每条成功确认报警都必须追加一条 `action = ack` 的日志记录
- **AND** 每条新增日志的备注内容必须与本次提交的统一 `operator_note` 一致
- **AND** 已确认或冲突失败的报警不得因此产生重复确认日志

### Requirement: 系统必须以部分成功结果返回批量确认处理结果

系统 SHALL 对批量确认中的每条报警独立处理，并返回逐条结果与汇总计数；其中某一条报警的冲突、已确认或不可见状态不得导致其他可确认报警整体回滚。

#### Scenario: 批量确认中部分报警成功而部分报警冲突

- **GIVEN** admin 在同一次批量确认请求中提交两条报警
- **AND** 第一条报警版本匹配且可确认
- **AND** 第二条报警在请求到达前已发生版本变化
- **WHEN** 系统处理本次批量确认请求
- **THEN** 系统必须成功确认第一条报警
- **AND** 系统必须将第二条报警标记为冲突结果
- **AND** 响应必须返回 `requested_count`、`acked_count` 和逐条结果状态

#### Scenario: 批量确认响应不返回冲突条目的最新版本号

- **GIVEN** admin 提交批量确认后，结果中包含 `conflict` 或 `already_acked` 条目
- **WHEN** 系统返回本次批量确认响应
- **THEN** 系统可以只返回这些条目的处理状态而不返回最新版本号
- **AND** 前端必须通过后续整页重拉恢复最新列表和详情状态

### Requirement: 系统必须在批量确认成功后保持现有报警同步语义

系统 SHALL 在批量确认成功后继续通过现有报警增量更新和汇总更新机制同步各客户端状态，而不是引入新的专用批量推送协议。

#### Scenario: 批量确认成功后相关客户端收到状态更新

- **GIVEN** admin 成功批量确认了当前页中的一条或多条报警
- **WHEN** 后端完成这些报警的状态更新与日志写入
- **THEN** 受影响区域的客户端必须收到这些报警的最新确认状态
- **AND** 相关报警汇总中的未确认计数必须同步更新

#### Scenario: 管理页在批量确认后通过整页重拉恢复一致状态

- **GIVEN** admin 管理页已经提交一次批量确认请求
- **WHEN** 前端收到本次批量确认响应
- **THEN** 管理页必须重新拉取当前列表页、汇总和当前详情
- **AND** 管理页不得依赖报警 Socket 增量事件来维持“当前页可见集合”的一致性
