# bundle-draft-editing Specification

## Purpose

定义管捆新增草稿、字段编辑权限、重号校验、管子编辑和派生值自动计算的行为，确保用户在保存前即可完成完整的数据整理。

## ADDED Requirements

### Requirement: 系统必须支持从合同数据创建新的管捆草稿

系统 SHALL 在用户输入合同号和项目号并点击“新增”后，根据合同数据生成新的管捆草稿；系统 MUST 复制合同数据中的可继承字段，并将需求中指定的字段置空，且该操作不得立即向后端提交保存。

#### Scenario: 新增草稿时从合同数据预填充可继承字段

- **GIVEN** 用户已输入合同号和项目号且合同数据存在
- **WHEN** 用户点击“新增”
- **THEN** 系统必须根据合同号和项目号查询合同数据
- **AND** 系统必须将合同数据中可继承的字段填入新的管捆草稿
- **AND** 系统必须保留页面未显示但保存所需的合同来源字段

#### Scenario: 新增草稿时指定字段必须置空

- **GIVEN** 系统已根据合同数据创建新草稿
- **WHEN** 草稿显示在中间管捆信息区
- **THEN** 管捆号、炉号、试批号、生产日期、生产时间、管捆状态、班组、作业点代码、去向代码必须为空
- **AND** 最短、最长、根数、最后流水号、理论重量、理论长度、米制重量、英制重量、米制长度、英制长度必须为空

#### Scenario: 新增草稿后不立即保存到后端

- **GIVEN** 用户刚创建新的管捆草稿
- **WHEN** 用户尚未点击“保存”
- **THEN** 系统不得向后端写入任何管捆或管子数据

#### Scenario: 新增草稿后管捆号输入框获得焦点

- **GIVEN** 新的管捆草稿已生成
- **WHEN** 页面完成草稿渲染
- **THEN** 中间区域的管捆号输入框必须获得输入焦点

### Requirement: 系统必须执行管捆字段的编辑权限规则

系统 SHALL 仅允许需求指定的管捆字段被人工编辑，其余字段 MUST 为只读；班组选择器 MUST 使用定义好的编码和值映射。

#### Scenario: 允许编辑指定字段

- **GIVEN** 用户正在编辑当前管捆草稿
- **WHEN** 用户尝试修改炉号、试批号、生产日期、生产时间、管捆状态、班组、作业点代码或去向代码
- **THEN** 系统必须允许这些字段被修改

#### Scenario: 非指定字段保持只读

- **GIVEN** 用户正在编辑当前管捆草稿
- **WHEN** 用户尝试修改合同号、项目号、外径、壁厚或其他未授权字段
- **THEN** 系统必须将这些字段视为只读
- **AND** 用户不得直接修改这些值

#### Scenario: 班组下拉框使用固定编码映射

- **GIVEN** 班组字段使用下拉框编辑
- **WHEN** 用户选择班组值
- **THEN** 系统必须支持 `11-夜甲`、`12-夜乙`、`13-夜丙`、`14-夜丁`、`21-早甲`、`22-早乙`、`23-早丙`、`24-早丁` 的对应关系
- **AND** 草稿中保存的值必须与选中的编码一致

### Requirement: 系统必须在管捆号变化时校验同合同同项目下的重号

系统 SHALL 在用户修改管捆号后请求后端验证当前合同号和项目号下是否已存在相同管捆号；若存在重复，系统 MUST 提示用户并阻止该重复值被视为有效草稿状态。

#### Scenario: 修改为已存在的管捆号时提示重复

- **GIVEN** 当前草稿合同号为 `O001`、项目号为 `01`
- **AND** 后端已存在同合同号和项目号下的管捆号 `B001`
- **WHEN** 用户将当前草稿的管捆号改为 `B001`
- **THEN** 系统必须提示该管捆号重复
- **AND** 系统不得将该值视为可正常保存的有效状态

#### Scenario: 修改为未重复的管捆号时通过校验

- **GIVEN** 当前草稿合同号为 `O001`、项目号为 `01`
- **WHEN** 用户将管捆号修改为不存在的值 `B099`
- **THEN** 系统必须通过重号校验
- **AND** 页面不得显示重复提示

### Requirement: 系统必须支持前端本地的管子新增、删除和编辑

系统 SHALL 支持用户在右侧管子表格中新增、删除和编辑管子记录，且这些操作在用户点击保存前 MUST 仅作用于前端草稿状态。

#### Scenario: 新增管子时创建默认行

- **GIVEN** 用户正在编辑某个管捆草稿
- **WHEN** 用户点击“管子新增”
- **THEN** 系统必须在右侧管子列表新增一条记录
- **AND** 新记录的流水号、管号、长度、重量必须初始化为 `0`

#### Scenario: 删除管子时移除选中行

- **GIVEN** 右侧管子列表已有多条记录且用户已选中其中一条
- **WHEN** 用户点击“管子删除”
- **THEN** 系统必须从当前草稿中删除该条管子记录
- **AND** 该删除操作在点击保存前不得立即提交到后端

#### Scenario: 编辑管子字段时仅更新草稿

- **GIVEN** 用户正在修改某条管子的流水号、管号、长度或重量
- **WHEN** 编辑操作完成
- **THEN** 系统必须更新当前前端草稿中的该条管子记录
- **AND** 不得在未保存时向后端提交更新

### Requirement: 系统必须在管子数据变化后自动重算派生字段

系统 SHALL 在新增、删除或编辑管子记录后，依据当前管子列表和合同米重自动更新管捆草稿中的派生字段，并严格使用需求中定义的计算规则和精度。

#### Scenario: 依据管子长度和重量重算管捆统计值

- **GIVEN** 当前草稿存在多条管子记录且合同米重已知
- **WHEN** 用户新增、删除或修改任意管子记录
- **THEN** 系统必须将“最短”更新为长度最小值
- **AND** 将“最长”更新为长度最大值
- **AND** 将“根数”更新为管子记录数
- **AND** 将“最后流水号”更新为流水号最大值

#### Scenario: 按需求公式重算重量和长度字段

- **GIVEN** 当前草稿存在多条管子记录且 `WEIGHT_PER_METER` 可用
- **WHEN** 系统执行重算
- **THEN** 理论重量必须等于长度总和乘以米重并取整
- **AND** 理论长度必须等于重量总和除以米重并保留 3 位小数
- **AND** 米制重量必须等于重量总和并取整
- **AND** 英制重量必须等于米制重量乘以 `2.204622` 并取整
- **AND** 米制长度必须等于长度总和并保留 3 位小数
- **AND** 英制长度必须等于米制长度乘以 `3.280839` 并保留 3 位小数

#### Scenario: 重算使用合同米重字段

- **GIVEN** 当前草稿合同号和项目号对应的合同数据存在 `WEIGHT_PER_METER`
- **WHEN** 系统重算派生字段
- **THEN** 系统必须使用该合同记录的 `WEIGHT_PER_METER` 作为计算米重
- **AND** 不得使用页面手工输入的替代值
