## Context

当前报警中心实现位于 `AlarmCenterPanel.vue`，并通过 `HomePage.vue` 以内嵌右侧面板的形式接入现有应用壳层。交互链路本身已经完整：页头按钮可打开面板，面板内包含摘要、筛选、分页、详情、确认和日志区，数据由独立的 alarm store 维护，实时更新依赖现有 HTTP 与 Socket 通道。

问题主要集中在视觉层。报警中心使用了一套偏暗黑、半透明、青蓝霓虹感较强的抽屉样式，而 MainMonitorView、AppHeader 以及当前 HMI 页面主体则是浅灰工业面板风格。主监控页已经具备较清晰的视觉规律：

- 使用浅灰底板和更浅的内容框体形成工业设备面板质感。
- 通过深浅边框、内嵌高光和悬浮标题标签制造层次，而不是依赖大面积深色背景。
- 在高密度布局下仍保持分区清晰，适合操作员连续使用。

因此，这次改造的核心不是重写报警能力，而是让报警中心回到统一的 HMI 视觉体系中，并在此基础上重新表达“待确认”“已确认”“已恢复”等状态层级。

## Goals / Non-Goals

**Goals:**

- 让报警中心与 MainMonitorView、AppHeader 和 HomePage 的视觉语言保持一致，消除当前暗黑主题割裂感。
- 在不改变数据结构和交互闭环的前提下，重构报警中心的框体层级、信息分组和状态强调方式。
- 保持报警中心的高密度、双栏、右侧处理面板模式，使操作员无需跳转页面即可完成查看与确认。
- 在浅色 HMI 主题中继续保持报警优先级表达，确保未确认和高等级报警仍然足够醒目。

**Non-Goals:**

- 不修改报警 HTTP API、Socket 事件、store 字段、分页逻辑或确认流程。
- 不新增独立报警路由页，也不把报警中心从 `HomePage` 壳层中拆出。
- 不重构整个系统的全局主题，只收敛报警中心及其入口的局部视觉风格。
- 不顺带调整与当前需求无关的业务交互、权限逻辑或后端数据契约。

## Decisions

### 1. 采用与 MainMonitorView 同源的浅灰工业 HMI 面板语言

报警中心的主体、分区框体和内部卡片统一回到 MainMonitorView 的浅灰工业风基线：外层底色使用浅灰壳层，内容区使用略深或略浅的分层面板，边框和内嵌阴影沿用主监控页已经建立的机械面板表达，而不再使用整面深色抽屉和高饱和霓虹背景。

这意味着报警中心的“高级感”不再依赖暗黑玻璃拟态，而是依赖更克制的材质层次、边框精度和节奏稳定的排版。这样既能与主监控页形成统一，又更符合工业监控界面的长期使用场景。

### 2. 保留右侧滑出式处理模型，只重做材质、分区和过渡语义

报警中心仍然保留“从 HomePage 右侧滑出”的交互模式，因为这一结构已经适配当前壳层，并且允许操作员在不离开业务页的情况下处理报警。改造不引入新的页面级导航，而是继续使用右侧面板，只对以下内容进行重构：

- 遮罩层强度改为更轻的中性遮罩，避免面板一打开就把整页压成暗黑环境。
- 面板主体改为浅色工业材质，边缘、阴影和进入动画改成更短、更稳的滑入反馈。
- 面板内部通过稳定框体而不是大面积纯色块来组织内容。

### 3. 面板内部采用“总览 - 筛选 - 双栏处理”的固定层级

报警中心内部的信息组织固定为四层：顶部标题区、摘要区、筛选区、主体双栏区。主体双栏区继续维持“左侧报警列表 + 右侧详情与日志”的结构，但每一层都用与主监控页一致的框体边界表达。

具体布局策略如下：

- 顶部保留报警中心标题，但使用更贴近主监控页的标题签或浮动标题感。
- 摘要数字卡不再表现为暗色高亮块，而改为嵌入式状态统计框体。
- 筛选区与页签区采用紧凑的控制面板风格，保证高频筛选操作更像 HMI 控制台而不是后台管理表单。
- 列表与详情的外壳分区清晰，选中态、悬停态和状态徽标都建立在统一浅色框体上。

### 4. 报警优先级强调依赖局部状态色，而不是整屏暗色对比

未确认、高等级和活动态报警仍然必须是视觉焦点，但强调方式改为“统一浅色壳层 + 局部高优先级状态色”，而不是通过全局暗背景来制造对比。推荐的状态语义是：

- `active + unacked`：使用最强的警示边框、角标或暖色背景强化。
- `active + acked`：保留活动态识别，但降低饱和度，转为较冷静的工业强调色。
- `cleared`：进入低对比、弱化表达，但仍保持可读性和日志追溯能力。
- `critical / major / minor / warning / info`：等级信息继续通过徽标、文字或边框差异保留，不因主题变浅而丢失区分度。

这样可以保证报警状态在视觉上依然可靠，同时不会破坏整体风格统一。

### 5. 页头报警入口与面板风格同步收敛

页头里的报警入口按钮目前处在浅色壳层中，但与弹出的暗黑面板并不一致。此次改造中，入口按钮的边框、底色、状态点和计数角标也需要同步校准，使用户在点击前后感受到的是同一套报警子系统，而不是两个分裂的主题。

入口本身仍然保留以下行为：

- 展示未确认数量。
- 支持零报警和有报警两种状态。
- 点击后打开同一面板。

变化只在于风格统一和状态可读性提升，不改变交互语义。

### 6. 逻辑边界保持不变，优先做组件级样式重构

这次 change 的实现边界明确限定在前端表现层。`alarmCenter` store、API 模块、Socket 事件处理、确认请求、筛选参数和数据结构都保持现状，避免把一次视觉重构扩展成跨层修改。实现时优先通过以下方式完成：

- 在 `AlarmCenterPanel.vue` 内重构模板分区类名和局部样式。
- 在 `AppHeader.vue` 内对齐报警按钮的视觉语言。
- 仅在必要时微调 `HomePage.vue` 的承载层、遮罩或定位样式。

这能把风险控制在最小范围内，同时让后续验证聚焦在前端 UI 一致性上。

## Validation Strategy

- 运行受影响前端范围的类型检查、构建或其他静态校验，确认样式重构没有破坏模板结构与类型引用。
- 在标准 1920 x 1080 HMI 布局下手动验证报警中心，确认不会引入浏览器级滚动条，也不会压缩到影响列表与详情可读性。
- 与 MainMonitorView 做并排或切换对比，确认背景、框体、标题层级、强调色和信息密度属于同一套视觉语言。
- 验证未确认报警、已确认报警、已恢复报警和无数据态在新主题下依然容易区分。
