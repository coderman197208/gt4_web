# bundle-query-and-detail-loading Specification

## Purpose

定义管捆查询、结果选择、明细联动加载的行为，确保 BundleManageView 能按业务规则加载完整的管捆与管子数据，并保留保存所需的隐藏字段。

## ADDED Requirements

### Requirement: 系统必须支持按日期窗口或管捆号查询管捆列表

系统 SHALL 在用户点击“执行查询”后，根据输入条件选择正确的查询模式；当管捆号为空时，系统 MUST 按输入日期对应的业务时间窗口查询管捆数据，当管捆号非空时，系统 MUST 按管捆号查询管捆数据。

#### Scenario: 管捆号为空时按业务时间窗口查询

- **GIVEN** 用户未输入管捆号且已输入查询日期 `2026-05-14`
- **WHEN** 用户点击“执行查询”
- **THEN** 系统必须按 `2026-05-13 19:45:00` 到 `2026-05-14 19:45:00` 的时间窗口查询管捆数据
- **AND** 查询结果必须显示在左侧管捆列表中

#### Scenario: 管捆号非空时优先按管捆号查询

- **GIVEN** 用户已输入管捆号 `B001`
- **WHEN** 用户点击“执行查询”
- **THEN** 系统必须按管捆号 `B001` 查询管捆数据
- **AND** 系统不得再使用日期窗口作为主查询条件

### Requirement: 系统必须展示查询结果并维护默认选中行为

系统 SHALL 将查询到的管捆结果显示在左侧列表中，并在存在结果时自动选中第一条记录；当没有查询结果时，系统 MUST 提示用户并清空管捆信息区与管子信息区。

#### Scenario: 查询到多条管捆记录时默认选中第一行

- **GIVEN** 查询返回 3 条管捆记录
- **WHEN** 系统渲染查询结果
- **THEN** 左侧管捆列表必须显示这 3 条记录
- **AND** 第一条记录必须自动进入选中状态
- **AND** 中间管捆信息区与右侧管子信息区必须加载第一条记录对应的数据

#### Scenario: 未查询到管捆记录时清空界面

- **GIVEN** 查询未返回任何管捆记录
- **WHEN** 系统完成查询处理
- **THEN** 系统必须提示用户未查询到记录
- **AND** 中间管捆信息区必须被清空
- **AND** 右侧管子信息区必须被清空

### Requirement: 系统必须在选择管捆记录时联动加载管捆明细和管子列表

系统 SHALL 在用户选中左侧管捆列表某一行时，加载该记录的完整管捆字段，并根据合同号、项目号、管捆号查询对应的管子数据后显示在右侧列表中。

#### Scenario: 用户点击不同管捆行时刷新中间和右侧区域

- **GIVEN** 左侧列表已展示多条管捆记录
- **WHEN** 用户点击其中一条管捆记录
- **THEN** 中间区域必须显示该记录对应的管捆字段值
- **AND** 右侧区域必须显示与该记录合同号、项目号、管捆号匹配的全部管子数据

#### Scenario: 选中记录后管子列表按键值加载

- **GIVEN** 选中的管捆记录合同号为 `O001`、项目号为 `01`、管捆号为 `B001`
- **WHEN** 系统发起明细联动加载
- **THEN** 系统必须按 `O001 + 01 + B001` 查询管子数据
- **AND** 右侧管子列表不得显示其他管捆的数据

### Requirement: 系统必须保留查询到的完整管捆记录字段

系统 SHALL 在查询和明细加载后保留管捆数据表中的完整记录，包括未显示在页面上的字段，以确保后续保存时不会丢失数据。

#### Scenario: 查询结果包含页面未显示字段时仍保存在当前草稿中

- **GIVEN** 后端返回的管捆记录包含页面未显示字段，如 `prod_code`、`prod_cname` 或其他业务字段
- **WHEN** 用户查询并选中该管捆记录
- **THEN** 系统必须将这些未显示字段一并保存到当前草稿数据中
- **AND** 后续保存前不得因页面未显示而丢弃这些字段

#### Scenario: 管子明细联动不覆盖隐藏字段

- **GIVEN** 当前草稿中已包含查询返回的完整管捆字段
- **WHEN** 系统继续加载该管捆对应的管子列表
- **THEN** 系统必须仅补充管子数据
- **AND** 不得清空或覆盖已保存的隐藏管捆字段
